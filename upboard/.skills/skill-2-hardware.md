# Skill-2: 硬件上下文感知

## 触发时机

- 全新项目，完成 skill-1 之后
- 新增外设或修改硬件配置时
- 遭遇硬件相关异常，需要重新核实硬件配置时

---

## 执行步骤

### 第一步：收集输入材料

请用户提供或确认以下材料的路径：

| 材料 | 说明 | 是否必须 |
|------|------|----------|
| 原理图 PDF / 图片 | 用于提取引脚连接关系 | 必须 |
| 数据手册（Reference Manual） | 寄存器定义、外设章节 | 必须 |
| CubeMX `.ioc` 文件 | 已配置的外设列表和引脚分配 | 有则提供 |
| 现有 BSP / 驱动代码 | 扫描已有驱动，避免重复或冲突 | 有则提供 |
| Errata Sheet | 芯片已知硅勘误 | 有则提供 |

### 第二步：从原理图提取引脚映射

读取原理图，提取所有与 MCU 相连的外设引脚，输出表格：

```markdown
## 引脚映射

| 外设 | 功能 | MCU 引脚 | 电平标准 | 上下拉 | 备注 |
|------|------|----------|----------|--------|------|
| UART1 | TX | PA9  | 3.3V | 无 | 调试串口 |
| UART1 | RX | PA10 | 3.3V | 无 | 调试串口 |
| I2C1  | SCL | PB6 | 3.3V | 外部上拉 4.7kΩ | BME280 |
| I2C1  | SDA | PB7 | 3.3V | 外部上拉 4.7kΩ | BME280 |
```

重点关注：
- 引脚复用冲突（同一引脚被多个外设使用）
- 电平转换需求（5V 外设接 3.3V MCU）
- 外部上下拉电阻是否存在及阻值

### 第三步：提取时钟树配置

从 CubeMX 文件或 Reference Manual 中确认：

```markdown
## 时钟树

- HSE：[外部晶振频率，例如 8MHz]
- PLL 倍频：[例如 × 9 = 72MHz]
- SYSCLK：
- AHB（HCLK）：
- APB1（PCLK1）：[注意：TIM2-7 在此总线]
- APB2（PCLK2）：[注意：TIM1/ADC 在此总线]
- USB 时钟：[如果使用 USB]
```

### 第四步：整理外设配置

每个使用到的外设输出一条记录：

```markdown
## 外设配置

| 外设 | 模式 | 关键参数 | 时钟源 | DMA | 中断 | 备注 |
|------|------|----------|--------|-----|------|------|
| UART1 | 异步 | 115200 8N1 | PCLK2 | 无 | 全局中断 | 调试输出 |
| I2C1  | 标准模式 | 100kHz | PCLK1 | 无 | 事件中断 | 传感器 |
| TIM3  | PWM | 1kHz | PCLK1×2 | 无 | 无 | LED 调光 |
```

### 第五步：检索 knowledge-base

根据当前项目使用的芯片型号和外设，检索：

1. **`known-bugs.md`**：搜索当前芯片型号 + 各外设关键词
   - 找到匹配项：在 hardware.context.md 中标注"已知问题：[描述]，见 known-bugs.md"
   - 没有匹配：继续

2. **`hal-patterns.md`**：搜索当前使用的外设类型
   - 找到匹配：在开发备注中标注可参考的模式

### 第六步：扫描现有 BSP / 驱动

如果项目已有代码，扫描 `Drivers/` 或 `BSP/` 目录：

- 列出已有驱动文件及其实现的功能
- 标注与本次开发可能冲突的部分
- 标注可以直接复用的部分

### 第七步：写入 hardware.context.md

将以上所有内容整理写入 `.context/hardware.context.md`，作为后续所有开发的硬件参考。

---

## 执行规则

- 不能凭记忆填写引脚配置，必须从原理图实际读取
- 时钟树配置必须与 CubeMX 实际配置一致，不能假设
- 发现引脚冲突或电平不匹配，立即上报，不得绕过
- 检索 knowledge-base 是必须步骤，不能跳过
- 如果某些材料用户无法提供，明确记录"未确认"，不得猜测填写
