# Skill-0: 项目记忆管理

## 触发时机

- 任意新会话开始
- 用户说"继续开发"、"新终端"、"换会话"
- 在执行其他任何 skill 之前

---

## 会话开始：冷启动握手

### 第一步：读取上下文文件

按顺序读取：

```
.context/project.context.md
.context/hardware.context.md
.context/decisions.log.md
```

如果文件不存在，说明是全新项目，执行初始化（见下方）。

### 第二步：复述项目状态

用一段话输出，包含：

- 项目名称和目标
- 已完成的模块（状态：✅）
- 进行中的模块（状态：🚧）和当前卡点
- 未开始的模块（状态：⬜）
- 当前 Flash/RAM 用量
- 遗留的已知问题

### 第三步：确认本次任务

输出：

```
本次任务：[用户描述的任务]
将使用：skill-[N]
完成后更新：[列出会变动的文件]
```

等待用户确认后再开始执行。

---

## 会话结束：写回

每次会话结束，或用户说"保存进度"、"更新状态"时执行。

### 更新 project.context.md

- 把本次完成的模块状态改为 ✅
- 更新 Flash/RAM 用量（从最近一次编译的 .map 文件读取）
- 更新 todo 列表
- 记录遗留的已知问题

### 追加 decisions.log.md

每条决策按格式追加，不修改历史：

```markdown
## [YYYY-MM-DD] <决策标题>

**背景**：[为什么需要做这个决策]
**决策**：[选择了什么方案]
**原因**：[为什么选这个，而不是其他方案]
**排除方案**：[试过或考虑过但放弃的方案，以及原因]
```

### 写回 knowledge-base（按需）

判断标准：本次会话发现的经验是否对其他项目也有价值？

- 发现某芯片的 HAL 已知 bug → 追加到 `knowledge-base/known-bugs.md`
- 总结出一个外设驱动通用套路 → 追加到 `knowledge-base/hal-patterns.md`
- 找到一个有效的故障排查路径 → 追加到 `knowledge-base/debug-recipes.md`
- RTOS 使用模式 → 追加到 `knowledge-base/rtos-patterns.md`

写回格式：追加到对应文件末尾，注明项目来源和日期。

## 执行规则

- 不得跳过冷启动握手直接开始开发
- 不得在未读取上下文的情况下修改代码
- 会话中途如果发现 hardware.context.md 有误，立即更正并记录
- 写回时如果不确定某个字段的新值，保留旧值并在 TODO 中标注
