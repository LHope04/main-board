## [串口] 串口日志过期误导诊断

- **症状**：读取 `serial_log.txt`，日志内容看起来"通过了"，但实际是烧录前的旧固件输出
- **根因**：`serial_log.txt` 是文件，不会自动清空。烧录新固件后如果 serial monitor 没有重启，文件仍保存旧内容
- **排查路径**：
```bash
# 1. 每次读串口日志前，先检查文件修改时间
stat "$SERIAL_LOG" | grep Modify

# 2. 对比修改时间和最后一次烧录时间，时间早于烧录 → 日志过期
# 3. 如果过期，重启 serial monitor 再等待新输出
"$PYBIN" "$SERIAL_MON" <COM_PORT> &
sleep 5
cat "$SERIAL_LOG"

# 4. 如果 COM 口报 PermissionError（已被占用），切换到内存直读
ST-LINK_CLI.exe -c SWD HotPlug -r32 <address> 1
```
- **根本预防**：优先用内存直读验证，串口只在内存读取无法回答问题时使用
- **检索关键词**：串口 · 日志 · 过期 · 旧输出 · 误判通过
- **来源项目**：upboard · 日期：—

## [通用] 内存直读优先于串口的诊断策略

- **适用场景**：任何验证阶段
- **原则**：
```
优先级：内存直读（HotPlug）> 串口日志 > 逻辑分析仪 CSV

内存直读的优势：
- 不需要串口连线
- 不打断 CPU 运行（HotPlug 模式）
- COM 口被占用时仍然可用
- 读取速度快，不受波特率限制
- 可以在任意时刻读取任意变量

只在以下情况才使用串口：
- 需要观察事件顺序（printf trace）
- 需要观察时序相关的输出
- 内存读取无法回答当前问题
```
- **HotPlug 读取命令**：
```bash
# 从 MAP 文件找变量地址
grep "变量名" "$MAP"

# 读取（每次只读 1 个 word，count > 2 不可靠）
ST-LINK_CLI.exe -c SWD HotPlug -r32 <address> 1
```
- **检索关键词**：验证 · 内存读取 · HotPlug · 串口 · 调试策略
- **来源项目**：upboard · 日期：—

## [I2C] 设备无响应 HAL_TIMEOUT

- **症状**：`HAL_I2C_Master_Transmit` 或 `HAL_I2C_Mem_Read` 始终返回 `HAL_TIMEOUT`
- **排查路径**：
```
1. 读 I2C SR1 寄存器，判断是地址阶段还是数据阶段失败
   ST-LINK_CLI.exe -c SWD HotPlug -r32 <I2C_SR1_addr> 1

2. 示波器探 SCL 引脚
   → 有 100kHz/400kHz 波形：时钟正常，进入步骤 3
   → 无波形：I2C 未初始化 或 引脚 GPIO 时钟未使能

3. 看 SDA 在地址帧第 9 个时钟是否被拉低（ACK）
   → 被拉低：地址正确，后续数据有问题
   → 未被拉低：设备地址错误 或 器件未响应

4. 确认设备地址：数据手册地址 + 硬件 ADDR 引脚状态（高/低）
   常见错误：忘记左移 1 位，或 ADDR 引脚接法与代码假设不符

5. 检查上拉电阻
   万用表量 SCL/SDA 空闲电压，应为 VCC（3.3V）
   → 低于 VCC：上拉电阻缺失 或 阻值过大 或 器件损坏拉死总线
```
- **结论**：90% 是地址错误或上拉缺失；10% 是器件损坏或供电问题
- **检索关键词**：I2C · TIMEOUT · 无响应 · ACK · NACK · 上拉
